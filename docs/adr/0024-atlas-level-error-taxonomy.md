# Atlas-Level Error Taxonomy

Atlas normalizes failures into one shared error vocabulary — the twelve classes already published as the REST API v1 `ErrorClass` enum — owned by a transport-neutral leaf package, `internal/apperr` (`Class`, `Error`, `LookupClass`). Providers normalize their upstream failures into these classes (ADR-0023 pins the Dashboard mapping) but do not own the vocabulary: store rejections (`Conflict` on closed Cases, `NotFound` lookups, `MalformedResponse` scan failures), API authentication and unsupported-mode failures (`Unauthorized`, `Unsupported`), and run-failure classification (`error_class` columns) all speak the same classes. The rejected alternative was layered per-package vocabularies with translation at each seam; it was declined because the classes were already the de-facto app-wide vocabulary (API enum, database columns, fixtures, contract tests) and a translation layer would add ceremony with zero behavior change.

The Go type mirrors the public wire enum byte-for-byte (`Internal` and `InvalidRequest` included), so wire output, OpenAPI, fixtures, and persisted `error_class` values are unchanged by construction. `Internal` is constructed only at fallback and failure-classification boundaries (the API's unmapped-error branch, sync and evaluation run classification), never as a deliberate validation rejection; caller-input rejections use `InvalidRequest`, which replaces the former `store.InvalidInputError` and `api.invalidRequestError` bolt-ons. The class-to-HTTP-status mapping stays in `internal/api`, which owns response behavior: `apperr` deliberately imports no transport library, because consumers span HTTP, database columns, and future Agent operation envelopes.

**Alternatives considered**: keeping the taxonomy in `internal/providers` and having other layers translate (inverted dependency — store, api, workflowdispatch, and casedetection would keep importing a sibling domain package for errors that are not about providers); moving only the type without folding in the 400-validation bolt-ons (leaves a two-vocabulary seam inside the API's error writer); promoting the class table out of `dev-plans/provider_contracts.md` §5 into its own doc (duplicates content; §5 stays the canonical table, reframed as the Atlas-wide vocabulary).

**Consequences**

- Every layer may import `internal/apperr`; it must stay a leaf (no Atlas imports) so the dependency graph stays acyclic.
- `internal/providers` no longer exports error types; `ProviderError` and `LookupErrorClass` disappear in favor of `apperr.Error` and `apperr.LookupClass`.
- Adding an error class now requires touching `apperr`, the OpenAPI enum, the `internal/api` status map, and `dev-plans/provider_contracts.md` §5 together — that coupling is deliberate, to keep code and public contract from drifting.
